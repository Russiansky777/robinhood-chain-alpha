## Метод и границы точности

Цена входа — фактическое уменьшение USDC кошелька / увеличение чистого количества токенов. Последующие значения — предельные котировки основного пула до расходов выхода и влияния продаваемого объёма, пересчитанные в USDC по последним восстановленным состояниям конверсионных пулов. Это не результат продажи всей позиции. Часть разницы со средней ценой покупки может возникать от влияния самой покупки на пул.

CRACKER: Raydium CPMM CRACKER/GP → Meteora DLMM GP/SOL → Raydium CLMM SOL/USDC. RUNNER: Raydium CPMM RUNNER/NKE → Raydium CLMM NKE/USDC. CLANKER: Raydium CLMM CLANKER/BOT → Raydium CLMM BOT/USDC; первая покупка дополнительно включала Meteora DLMM CLANKER/SOL. Для неё показана котировка основного CLMM, а не взвешенная выручка двух пулов.

Горизонты определены по реальному blockTime, с точностью секунд, не по фиксированной длительности слота. CPMM: резервы после обмена с учётом долей protocol/fund/creator; CLMM: квадрат sqrtPriceX64 с поправкой на decimals; DLMM: цена конечного bin. Резервы проверены на 43 переходах внутри сохранённых блоков без расхождений. Две транзакции с обрезанными журналами проверены по внутренним вызовам: нужные события целевого пула сохранились полностью.

Возраст котировки в таблице ниже — разница между целевой секундой и последним восстановленным обменом. Если по истории конверсионного пула проверено отсутствие более поздних обменов, перенос его состояния корректен; там, где этот поиск не завершён, пересчёт в USDC остаётся оценкой, а не точно подтверждённой котировкой на контрольную секунду. Старые котировки не подменяются текущими. Файл quote_checks.json перечисляет завершённые проверки конверсионных пулов; отсутствие записи при ненулевом возрасте не доказывает отсутствие более поздних обменов.

## Что осталось неполным

Полный подсчёт последующих обменов и часть проверки последних конверсионных котировок не завершены. Не проверена абсолютная полнота покупок через старые закрытые токен-счета. Котировки не моделируют продажу всего объёма, изменение ликвидности от нашей дополнительной сделки и расходы исполнения выхода. По четырём входам нельзя оценить устойчивость стратегии.

Публичный PublicNode отказал в индексированном getTokenAccountsByOwner без персонального токена и в одном getMultipleAccounts; эти чтения выполнены через api.mainnet-beta.solana.com. Для истории и блоков использован PublicNode с сохранением ответов. В этом прогоне не заявляется новый 429: ограничение 429 относится к предыдущему анализу WOW.

Архив содержит исходные ответы RPC, код, промежуточные результаты, журналы и отчёт. Для локального пересчёта по кэшу: python solana_three_check/calculate.py; python solana_three_check/wave_bounds.py. Сетевые загрузчики — сохранённые этапы работы, не единый конвейер для автоматического перезапуска.
