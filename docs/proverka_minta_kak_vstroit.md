# Проверка токена до входа: как встроить (для Code-1)

Модуль: `analysis/c3_proverka_minta.py` (самопроверка **16/16**).
Ничего не запрещает — даёт флаги и числа. Пороги ставит тот, кто решает.

## 1. Главное: это уже читается, просто выбрасывается

`bloom_detector` перед покупкой читает минт (`getMultipleAccounts`,
`encoding=jsonParsed`, кеш на минт) и берёт оттуда **два** поля: ставку налога
и полномочия. В том же ответе лежит остальное.

**Замер по 173 живым минтам наших сделок** (`data/a2_mint_tax_fill.json`,
26.09; Token-2022 — 153 из них):

| расширение | у скольких минтов | чем опасно |
|---|---|---|
| `transferFeeConfig` | 104 | налог: часть продажи уходит эмитенту |
| `transferHook` | **21** | при каждом переводе зовётся **чужая программа** — может не дать продать |
| `permanentDelegate` | **21** | эмитент вправе забрать токены **с нашего счёта** без нашей подписи |
| `defaultAccountState` | **21** | новые счета могут создаваться **замороженными**: купить можно, продать нельзя |
| `pausableConfig` | **21** | эмитент может **остановить переводы** в любой момент |
| `metadataPointer` / `tokenMetadata` | 153 | безобидно |

То есть **опасная четвёрка встречается у каждого восьмого** нашего минта, и
сейчас полоса о ней не знает ничего.

## 2. Как встроить

```python
import c3_proverka_minta as PM
с = PM.svodka(info, programma=owner, krupnejshie=None)   # info = data.parsed.info
# с["itog"]    -- "чисто" | "есть флаги" | "не известно"
# с["opasnyh"] -- сколько опасных флагов
# с["pochemu"] -- словами, по каждому
# с["flagi"]   -- числами: ставка налога, программа хука, адрес делегата...
```

Встраивается **в то же место**, где сейчас читается налог
(`bloom_detector.налог_минта` / `налоги_минтов`) — **без второго чтения**.
Разбор самого тяжёлого минта (восемь расширений, оба полномочия) занимает
**0.005 мс** при пределе 5 мс.

## 3. Два слова, которые нельзя путать

`"не известно"` ≠ `"чисто"`. Если минт не разобран или поля `extensions` в
ответе нет — итог **«не известно»**, а не «опасного нет». Это ровно та ошибка,
которую ты уже чинил у налога (`ноль_доказан`): два разных случая сливались в
один, и полоса считала ноль доказанным. Здесь они разведены и это доказанный
красный в самопроверке.

Незнакомое расширение **не выбрасывается молча** — оно называется по имени
(`neizvestnyh_rasshirenij`), чтобы новое расширение Token-2022 не прошло мимо.

## 4. Доли крупнейших держателей

В **том же** чтении их нет: это другой вызов (`getTokenLargestAccounts`,
+1 кредит). Модуль принимает их отдельным аргументом и считает доли первого и
первых пяти; не дали — говорит **«нет в этом чтении»**, а не ноль.

## 5. Что нужно от Code-1

Ничего нового снимать не надо: всё берётся из ответа, который полоса уже
получает. Решение одно — **хотите ли вы второе чтение** (`getTokenLargestAccounts`)
ради доли держателей. Если да, порог по доле даст Code-2 (п.8 его пакета), а
модуль уже готов его принять.
