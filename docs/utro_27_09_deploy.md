## Шаг 0. Один деплой кода (при нуле открытых позиций)

Прогон деплоя детектора и сторожа с боевой ветки. В окружение службы добавить
ровно две строки (обе — не включение торговли, а адреса и предел):

* `BLOOM_COPIERS_FILE=/home/bot/bloom_executor_live_data/kopirovshchiki.json`
  — иначе список копировщиков читается из каталога кода и всегда пуст.
* `BLOOM_LANE_MAX_POOL_FEE=0.05` — потолок комиссии пула (см. ниже). Если
  владелец назовёт другое число — поставить его.

Флаги торговли (`BLOOM_CLOSE_ON_SELL`, `BLOOM_TG_FORMAT`, `BLOOM_REGION_SEND`,
`LANE_*`) в этот деплой НЕ ставятся: они включаются потом.

Что входит в код этого деплоя:

1. Закрытие токен-счёта при продаже (`analysis/bloom_close_on_sell.py`, 16/16).
2. Формат Telegram по пакету владельца плюс заполненные поля строки BUY: имя
   токена из цепи, место в блоках, разложение пути, кто довёз, парная строка
   Bloom; соседи по слоту и список копировщиков собираются фоном.
3. Региональная отправка (`analysis/bloom_region_send.py`, 26/26).
4. Предел открытых позиций полосы — поле группы `lane_open_max`.
5. Сборщики: разновидность кривой pump.fun `c2ab1c46684d5b2f` (27 счетов,
   котировка минтом), Meteora DAMM v2 (цена по событию свопа), Meteora DBC.
6. Потолок комиссии пула на денежном пути.

## Порядок включения ПОСЛЕ деплоя (по одному, без перезапусков)

Включение — правкой ФАЙЛА, не окружения: файл групп детектор перечитывает на
ходу. Поле `lane_pools` группы перечисляет типы пулов сверх постоянных Pump AMM
и Raydium CPMM; список в файле сильнее флагов окружения, пустой список — как
отсутствие поля.

1. **Закрытие счёта при продаже.** `BLOOM_CLOSE_ON_SELL=1` — это окружение,
   поэтому оно ставится ещё в шаге 0 (по слову владельца) либо ждёт следующего
   перезапуска. Проверка: одна живая сделка, по цепи видно возврат ренты.
2. **Формат Telegram.** `BLOOM_TG_FORMAT=2` — тоже окружение, там же.
3. **Предел открытых 1 → 3** — файлом: `run_vps_group_policy_nl.yml`,
   `field=lane_open_max`, `set=3` по `bloom_lane`, `lane_only`, `candidates`.
   Перезапуск не нужен.
4. **Кривая pump.fun** — файлом: `lane_pools=["bonding"]` у одной группы
   (владелец 26.09 просил начинать со `speed_only`), одна живая сделка 0.01.
5. **Meteora DAMM v2** — файлом: добавить `"damm2"` в `lane_pools` той же
   группы. Перед включением прогон симуляции:
   `run_sborshchik_sim_nl.yml` с `program=cpamdpZCGKUy5JxQXB4dcpGPiikHawvSWAd6mEn1sGG`.
6. **Meteora DBC** — файлом: добавить `"dbc"`. Симуляция обязательна: схема
   события снята с ДВУХ живых сделок, этого мало.
7. **Региональная отправка** — `BLOOM_REGION_SEND=1` (окружение, следующий
   перезапуск), число: доля S+0 на лидерах вне EU до и после.

## Потолок комиссии пула — решение владельцу

В живой сделке 26.09 пул Meteora брал **50.9 %** комиссии (расписание комиссии
свежего пула), и модель цены при ней воспроизвела сделку источника точно, то есть
это правда, а не ошибка разбора. Покупать с такой комиссией — отдать половину
входа пулу. Поэтому на денежном пути стоит `BLOOM_LANE_MAX_POOL_FEE`, по
умолчанию **5 %**; отказ называет число. Порог — решение владельца.

## Meteora DLMM — не сделан, и почему

У DLMM ликвидность в бинах: в каждой живой сделке источник проходил 4–5 бинов
(видно по полям start/end bin в событии), и цена одной сделки не переносится на
нашу без чтения массивов бинов из цепи. Это отдельный шаг, а не «ещё один
сборщик»; вслепую включать нельзя.
