## Ночные находки, которые стоят денег (все проверены)

1. **Суточный стоп Bloom не срабатывает никогда.** Гейт в
   `bloom_exec_state.py:748` сверяет `realized_sol` с `BLOOM_DAILY_LOSS_SOL`, а
   писать `realized_sol` умеет только `add_pnl` (строка 618), которую в боевом
   коде не зовёт никто: вызовы только в самопроверке того же модуля (1001,
   1004). Счёт всегда 0.0, условие не выполняется. То же нулевое значение
   владелец видит в ответе `/status`.
2. **Ротация журнала обнуляет суточные счётчики полосы.**
   `ExecState.positions()` читает только текущий `positions.jsonl`, а logrotate
   в 22:00Z уводит сутки в `.1.gz`. В признаке жизни 22:25Z полоса показала
   `today: 0, pnl_sol: 0.0` после 25 покупок за вечер. Пределы (50 сделок,
   стопы -0.3/-0.5, потолок 1 SOL) считаются по пустому журналу, то есть
   каждую полночь по хосту стоп-лосс начинается с нуля. Позиция, открытая в
   момент ротации, исчезла бы из виду сторожа (сегодня открытых не было).
3. **Общий файл KILL глушит и полосу.** Полоса сверяется с
   `состояние.kill_active()` раньше своего `KILL_OWN_SEND`
   (`bloom_own_send.py:1323, 2359, 2477`). Отдельного выключателя только для
   Bloom нет -- утром развести на два файла (поручение владельца).

## САМОЕ ГЛАВНОЕ: стоп Bloom за сутки не работает вовсе

Найдено на часовой самопроверке 21:2xZ, проверено по коду, не догадка.

* Гейт есть: `bloom_exec_state.py:748` отказывает в покупке, если
  `-pnl()["realized_sol"] >= daily_loss_sol` (код КОД_ДНЕВНОЙ_УБЫТОК).
* Записывать в этот счёт умеет только `add_pnl` (строка 618). **В боевом коде
  её не зовёт никто**: во всём репозитории вызовы только в самопроверке того
  же модуля (строки 1001 и 1004). Ни детектор, ни сторож продаж, ни
  исполнитель не пишут `realized_sol`.
* Значит файл `pnl_ГГГГММДД.json` не создаётся, `realized_sol` всегда 0.0, и
  условие `0.0 >= 0.5` (или 1.0) НИКОГДА не выполняется. Величина
  `BLOOM_DAILY_LOSS_SOL` (в коде по умолчанию 1.0, деплой сторожа пишет 1)
  сегодня не значит ничего.
* Тот же нуль владелец видит в ответе на `/status`: строка "за сутки:
  покупок 0, продаж 0, результат 0.0 SOL" (bloom_detector.py:8744) всегда
  нулевая, и это читается как "потерь нет".
* Что у Bloom РАБОТАЕТ: рубильник KILL, автопаузы (5 ошибок API подряд, 3
  непроданных подряд, 429 дольше 5 минут), кулдаун по минту и проверка
  баланса. Последняя и есть фактический стоп: покупки прекратятся, когда на
  кошельке станет меньше `buy_sol + резерв` (~0.21 SOL), то есть почти при
  пустом кошельке, а не на -0.5.
* У полосы стопы РАБОТАЮТ, они считаются по позициям, а не по этому файлу
  (денежная группа -0.3, скорость -0.5, 5 упавших подряд, 1 открытая, 50 за
  сутки). Но у денежной группы 5 сделок из 6 сегодня "несчитаемые", поэтому и
  её стоп видит меньше настоящего убытка.

Утром: писать realized_sol там, где продажа уже разобрана (сторож знает
sol_delta_net), и только после этого проверять величину предела. До тех пор
ночной стоп Bloom существует лишь как рука владельца: `/kill` в Telegram
запрещает новые покупки без всякого деплоя, `/resume` снимает.
