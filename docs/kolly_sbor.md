## Шаг 2 — как выбирается актор (кодом, не памятью)

Store спрашивается по API (`GET /v2/store?search=…` по словам «tweet scraper»,
«twitter scraper», «x scraper»), из ответа берутся модель оплаты, цена за
результат и дата правки. Берутся **только акторы с оплатой за результат**
(`PRICE_PER_DATASET_ITEM`): лишь с ними счётчик расхода работает ДО запроса, а с
подпиской или оплатой за событие потолок проверять нечем. Отсев и выбор — **цена
за 1000 постов первым ключом, дата правки вторым**, потолок цены 1 $ за 1000.
Схема входа читается у сборки выбранного актора
(`/acts/{id}` → `taggedBuilds` → `/actor-builds/{id}` → `inputSchema`), и имена
полей берутся **из неё** по списку кандидатов (аккаунты, начало и конец окна,
предел строк). Нет нужного поля — отказ по имени со списком того, что схема
действительно принимает, а не запуск наугад за деньги. Выбор и разбор схемы
пишутся в `data/kolly/aktor_vybor.json`.

## Шаг 3 — потолок и окно

* **Счётчик ДО каждого запроса, по худшему случаю** (полный предел строк): не
  дороже 5 $ и не больше 60 запросов. После ответа деньги уже потрачены, и
  проверять там — проверять веру.
* Сколько постов влезает в бюджет, считается **из прочитанной цены**:
  `предел_постов = 5 $ / цена`, на аккаунт — делённое на пятьдесят. Меньше 20
  постов на аккаунт — **отказ**, а не молчаливое урезание окна.
* Окно задания — `2026-09-24T00:00:00Z … 2026-10-01T23:59:59Z`. У актора
  запрашивается с запасом (до `2026-10-02`, потому что у многих акторов дата
  задаётся без времени), а **точную границу ставит свой фильтр по времени каждого
  поста**, а не доверие актору. Вид даты (с временем или без) берётся из примера в
  самой схеме.
* Сырые ответы сохраняются как есть в `data/kolly/syrye/`.

## Формат выхода — ровно как просил Code-2

`data/kolly/kolly_2026-09-24_10-01.json` — список объектов, порядок ключей такой:

```
{"mint": "<base58 32–44>", "t_utc": "<YYYY-MM-DDTHH:MM:SSZ>",
 "author_handle": "<handle>", "post_url": "<https://x.com/…/status/…>",
 "author_wallet": "<адрес или пустая строка>", "text": "<текст поста целиком>"}
```

`t_utc` всегда с секундами. `author_wallet` пустой, если связки для этого handle
нет — пустое поле лучше чужого кошелька. `post_url` берётся из ответа актора, а
если его там нет — собирается из handle и id поста; не вышло ни то, ни другое —
пустая строка, и такие посты посчитаны отдельно.

**Что считается коллом:** подстрока base58 длиной 32–44 знака (в том числе с
окончанием `pump`), которая разбирается как 32-байтовый ключ Solana
(`solders.Pubkey.from_string`). Границы обязательны: без них 88-значная ПОДПИСЬ
транзакции давала бы совпадение первыми 44 знаками и попадала бы в коллы — это
проверено в самопроверке.
