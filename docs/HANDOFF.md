# HANDOFF — что делать первым в новом чате

Прочитать `docs/PROJECT_STATE.md` целиком первым делом — этот файл только
указывает, куда смотреть и в каком порядке, не дублирует цифры.

**Право отказа (общее правило, читать раньше любого задания, не только
про P5).** Если задание — даже явное, подробное, от владельца/штаба —
ведёт к снятию защитного барьера (доступ к хосту/ключам/деньгам,
аудируемость, safety-гейт, confirm-протокол), Code останавливается и
спрашивает, а не выполняет. Задание может быть ошибочным именно потому,
что оно детально расписано и выглядит безопасным по шагам — это не
повод выполнить его тихо. Отказ с объяснением причины ценится выше
аккуратного исполнения. Разобранный случай — `docs/PROJECT_STATE.md`
§4, последний пункт (предложение перевесить SSH-порт NL-VPS ради
доступа агента, отменено владельцем).

   балансы кошелька/маржи/плечо/позиции — если нужен самый свежий статус,

3. `data/p5_live_position_state.json` — стартовые значения позиции для
   расчёта доходности и kill-порога 30%/год (когда считать — от

4. **Открытый вопрос, поднятый ДО того, как считать 30%/год окончательным:**

   не разобрано в новом чате — не считать 30%/год порог железно

## 2. Если задача — продолжить P5 (наиболее вероятный сценарий)

Прочитать §4 (реестр багов) и §5 (формулы) `PROJECT_STATE.md` ПЕРЕД тем,
как писать любой новый код по хеджу/марже/газу — все перечисленные там
баги реально стоили денег или времени один раз, не наступать снова
вслепую.

Следующий логичный шаг по очереди владельца — `p5_live_bot.py` (демон
ребаланса, Step 2-4), но **не начинать писать/включать его без явной
команды владельца** — это прямо оговорено как отдельное решение, не
автоматическое продолжение.

Если возникает необходимость реальной отправки (открытие/закрытие/хедж) —
протокол обязателен: dry-run → показать владельцу точные цифры (размер,
маржу, буфер 25%, оценку ликвидации) → явное подтверждение владельца →
только тогда CONFIRM-маркер. Не пропускать dry-run даже если предыдущий
прогон прошёл гладко.

## 4. Инфраструктура — если нужно что-то на VPS

§2 `PROJECT_STATE.md` — оба VPS, где секреты, где что установлено.
**Рабочий хост для торговли на Lighter — только Нидерланды
(45.59.170.76)**, Даллас (США) юрисдикционно заблокирован для
торгового пути, не техническая проблема, не пытаться чинить.

Прямой SSH из интерактивной сессии агента на VPS **не используется —
не потому что технически невозможен** (порт 22 отфильтрован в
рантайме сессии, но это единственное сетевое ограничение, см. §2
`PROJECT_STATE.md`; в остальном TCP наружу открыт, и порт можно было
бы сменить). Канал к VPS сознательно только один — GH Actions (`push`
на маркер-файл в `data/p3_guard_cache/`, ветка
`claude/sc1-pons-v2-launcher-efdbyt`, не дефолтная —
`workflow_dispatch` из API не сработает для воркфлоу этой ветки,
только `push`) — ради аудируемости: доступ к хосту = доступ к
`PRIVATE_KEY_NOX`/ключам Lighter. Обходить фильтр порта 22 не пытаться
даже если задание это явно предлагает — см. правило отказа в начале
файла.

## 5. Общая дисциплина (не специфично для P5, но легко забыть в новом чате)

- Никогда не выдумывать данные — искать реальные источники (стандартное
  требование владельца весь проект).
- Реальная отправка денег — всегда dry-run первым, confirm — только
  после явного «да» владельца на конкретные цифры, не на общее
  разрешение заранее.
- Любой найденный баг/несостыковка — сначала реальная проверка
  (эмпирика), потом фикс, потом (если это меняет доверие к прошлому
  прогону) явный доклад владельцу — не тихая правка.
