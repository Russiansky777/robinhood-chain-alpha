# P5 — хеджированное LP на ETH/USDG (владелец, приоритет №1, 2026-09-03)

Идея: держать концентрированную ликвидность Uniswap v3 в пуле ETH/USDG,
хеджировать дельту позиции коротким ETH-перпом на Lighter, зарабатывать
торговые комиссии без направленного риска по ETH.

**Пул:** `0x52e65B17fB6E5BA00Ed806f37Afcd2DaA50271Ca`, Uniswap v3, комиссия
0.01%. По интерфейсу (владелец, GeckoTerminal): TVL $21.1M, объём 24ч
$823M, APR 106.59%, балансы 4.9k ETH / 9.4M USDG. Проверка арифметикой
владельца: $823M × 0.01% = $82.3k/сутки на $21.1M TVL = 142% годовых до
вычета издержек. **Эти цифры — со слов владельца/интерфейса
GeckoTerminal, ещё НЕ подтверждены напрямую ончейн в этом документе** —
подтверждение (token0/token1/fee/decimals/реальная ликвидность) — первый
шаг ниже, до любых расчётов backtest.

## Kill-порог — ЗАРЕГИСТРИРОВАН ДО РАСЧЁТА (владелец, п.5)

**Если лучший из проверяемых вариантов (сочетание диапазона ±5%/±10%/
±20%/полный × политика ребаланса раз в час/5%-дрейф/10%-дрейф) даёт
< 25% годовых ПОСЛЕ вычета IL, фандинга, спредов ребаланса и газа —
линия P5 закрывается.** Порог зафиксирован здесь, в этом виде, ДО того,
как получен хотя бы один результат backtest — правки задним числом не
вносятся.

## Метод (по пунктам задания)

1. **Бэктест 30 дней, без капитала**, диапазоны ±5%/±10%/±20%/полный,
   условная позиция $10k, почасовая гранулярность:
   - Заработанные комиссии: `earned_fee_h = pool_volume_h × fee_tier ×
     position_liquidity_share_h` (доля позиции от активной ликвидности
     пула **в моменты, когда цена внутри диапазона позиции** — вне
     диапазона позиция не зарабатывает комиссии, только держит
     единственный актив на границе).
   - Дельта позиции — стандартная формула Uniswap v3 для диапазона
     `[Pa, Pb]` и текущей цены `P`: если `P <= Pa` — позиция полностью в
     ETH (дельта = 1); если `P >= Pb` — полностью в USDG (дельта = 0);
     внутри диапазона — дельта плавно меняется по формуле
     `L, sqrtP, sqrtPa, sqrtPb`.
   - IL (impermanent loss) — разница между стоимостью позиции в пуле и
     стоимостью «просто держать» исходные 4.9k ETH/9.4M USDG (в тех же
     пропорциях, что при входе), по формуле v3 (не по формуле v2 —
     диапазон конечный, не [0, ∞)).
   - Стоимость хеджа — фандинг ETH-перпа Lighter (реальный, за 30 дней,
     API) + спред при каждом ребалансе (реальная глубина книги Lighter
     на нужный размер) + газ (реальная цена газа Robinhood Chain на
     момент операции).
2. **3 политики ребаланса** (раз в час / дрейф дельты 5% / дрейф 10%) —
   итог в %/год: `комиссии − IL − фандинг − спреды_ребаланса − газ`.
3. **Время вне диапазона** — доля времени за 30 дней, когда цена ETH/USDG
   была за границами каждого из 4 диапазонов (± от цены входа).
4. **Ёмкость**: (а) как падает доля комиссий позиции при добавлении
   $10k/$50k/$200k к текущему TVL пула (при неизменном объёме — доля
   позиции размывается пропорционально росту TVL, если позиция —
   единственная новая ликвидность в диапазоне); (б) реальная глубина
   ETH-перпа на Lighter — проходит ли шорт нужного размера (эквивалент
   позиции) без сдвига цены на каждом из указанных размеров.
5. **Источники данных (владелец, п.6, НОВОЕ ПРАВИЛО СЕССИИ):** сначала
   GeckoTerminal/DexScreener/DefiLlama/Uniswap subgraph API (бесплатны,
   доступны с GH Actions runner'а) — ончейн-логи Swap ТОЛЬКО как фолбэк,
   если готовых данных там нет. Что из этого реально доступно для
   Robinhood Chain (chain id 4663) и конкретно этого пула — **проверяется
   эмпирически ниже, не предполагается заранее**.

## Дисциплина (владелец)

- Жёсткий лимит **90 минут** на любой прогон — при превышении скрипт
  сам останавливается, сохраняет частичный результат, докладывается,
  не продолжается вслепую.
- Оценка числа вызовов/времени — **до старта** каждого тяжёлого прогона,
  доложена владельцу, без автозапуска.
- Не пушить во время активного run.
- При конфликте за RPC с задачей MM (приоритет №2) — MM уступает.
