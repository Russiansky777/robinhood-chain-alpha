# DLMM без чтений: тень для `lane_dlmm_nol_godilos`. Как встроить

**Файл:** `analysis/c2_dlmm_bez_chteniy.py`. **Флаг:** `BLOOM_DLMM_BEZ_CHTENIY` /
`BLOOM_DLMM_BEZ_CHTENIY_GROUPS`, по умолчанию ВЫКЛЮЧЕН.
**Самопроверка:** `python3 analysis/c2_dlmm_bez_chteniy.py --self-test` — **34/34**.
**Замер и сверка:** `deploy/checks/dlmm_bez_chteniy_chislo.py`.

## Что это и чего это НЕ делает

Третья ступень лестницы: два чтения → одно чтение → **нуль чтений**. Цена берётся из
**события свопа источника**: он только что прошёл по этому пулу и сказал, сколько
отдал за сколько (`amount_in`, `amount_out`) и сколько корзин пересёк
(`start_bin_id`, `end_bin_id`). Мы применяем ту же цену к своему размеру. Сети не
нужно ни на байт, `rpc_call` в котировке принимается только для совместимости
подписи и в теле не используется (это проверяется самопроверкой).

**Решений модуль не принимает.** `тень()` не отдаёт `min_out` для отправки — в ответе
только числа; это тоже проверка в самопроверке. Ничего в решении полосы не меняется.

## Три числа: модуль против замера, до единицы

На 31 считаемом свопе сбора Code-2 (`dlmm_bez_chteniy_sbor.json`, 46 свопов):

| что | число |
|---|---|
| посчитано модулем / замером | **31 / 31** |
| цена совпала **ДО ЕДИНИЦЫ** | **31 из 31** |
| отказов модулем / замером, из них той же причиной | **15 / 15, той же причиной 15** |

Корзины нашего размера: доказано **14**, оценка **17** (см. ниже, что это значит).

Определение цены у замера и у модуля **одно** — целочисленно вниз
`наш_вход * его_выход // его_вход`. Это сказано нарочно: считай замер во float, а
модуль в целых — сверка «до единицы» расходилась бы на единицу, и выглядело бы это
как ошибка модуля.

## Три отказа, все по имени

1. **`своп источника шёл в другую сторону`** — у DLMM обратная сторона это другие
   корзины и другая комиссия, цену как есть применить нельзя. В замере это 15 из 46,
   и это **не ошибка предсказания, а «сказать нечего»**.
2. **`события свопа этого пула в сделке источника нет`** — считать не из чего.
   События чужих пулов отбрасываются по адресу пула: на сделке роутера иначе взяли бы
   чужой пул.
3. **Налог выхода на Token-2022 без названного числа** — отказ, а не ноль (то же
   правило, что у строителей: молчаливый ноль завышает минимум и даёт откат).

## Корзины нашего размера: где доказано, а где оценка

* наш вход **не больше** его входа → корзин **не больше**, чем у него. Верхняя
  граница **доказана**: меньший вход не может уйти дальше по кривой.
  `корзин_доказано=True`.
* наш вход **больше** → из события не видно, сколько ликвидности лежит за его
  последней корзиной. Даём линейную оценку и помечаем `корзин_доказано=False`:
  за границей его свопа ликвидности может не быть вовсе.

## Как встроить: один вызов и два поля (правка в твоём файле, я её не делал)

Рядом с уже стоящей тенью одного чтения, тем же порядком. В
`analysis/bloom_own_send.py`:

**1. Обёртка** — рядом с `тень_одного_чтения` (строка ~1958):

```python
def тень_нуля_чтений(tx_источника, пул, к, *, лампорты, минт_котировки) -> dict:
    """Годился ли путь НУЛЯ чтений. Ноль чтений, решений не принимает."""
    try:
        import c2_dlmm_bez_chteniy as НЧ  # noqa: PLC0415
    except Exception as exc:  # noqa: BLE001
        return {"годилось": None, "почему_нет": f"модуля нет: {type(exc).__name__}"}
    if not НЧ.включён():
        return {"годилось": None, "почему_нет": "тень нуля чтений выключена флагом"}
    return НЧ.тень(tx_источника, пул, к, лампорты=лампорты,
                    минт_котировки=минт_котировки)
```

**2. Вызов** — в `массивы_dlmm_сейчас`, сразу за уже стоящим
`из_["одно_чтение_тень"] = …` (строка ~2066):

```python
        из_["нуль_чтений_тень"] = тень_нуля_чтений(
            tx_источника, (tpl.get("accounts") or [None])[0], к,
            лампорты=лампорты, минт_котировки=(mv or {}).get("quote_mint"))
```

**3. Доступ** — рядом с `тень_dlmm` (строка ~260), тем же правилом «нет раздела →
`(None, None)`, а не выдуманный ноль»:

```python
def тень_dlmm_нуль(сб: dict) -> tuple:
    д = (сб or {}).get("dlmm")
    т = (д or {}).get("нуль_чтений_тень") if isinstance(д, dict) else None
    if not isinstance(т, dict):
        return (None, None)
    г = т.get("годилось")
    return (г if isinstance(г, bool) else None, т.get("почему_нет"))
```

**4. Два поля в запись позиции** — рядом с `lane_dlmm_odno_godilos` (строка ~5843):

```python
                lane_dlmm_nol_godilos=тень_dlmm_нуль(сб)[0],
                lane_dlmm_nol_why_not=тень_dlmm_нуль(сб)[1],
```

**5. В выгрузку** — рядом с `lane_dlmm_odno_godilos` в
`deploy/checks/sdelki_polosy_vygruzka.py` (строка ~560):

```python
            "lane_dlmm_nol_godilos": п.get("lane_dlmm_nol_godilos"),
            "lane_dlmm_nol_why_not": п.get("lane_dlmm_nol_why_not"),
```

## Что значит `годилось` в бою — и это главное число для штаба

Не «цена посчиталась», а **«посчиталась И НЕ ЗАВЫШЕНА»** против прежней точной цены
полосы (`к["expected_out"]`). Завышение — это `min_out` выше того, что пул отдаст,
то есть откат и сожжённая комиссия; считать его удачей нельзя.

Насколько завышено — в поле `запас_нужен_%`. **Это и есть тот запас, который штабу
пришлось бы отдавать с каждой покупки**, если бы путь включили. На журнальной
выборке его максимум +6,64 %; в бою отставание меньше, и число будет своё — за этим
поле и ставится.

Если точной цены полосы в ответе нет, тень возвращает `годилось=None` и
«сверить не с чем», а **не** `True`: иначе в выгрузке появилось бы True там, где не
сверяли ничего.

## Чего в этом ответе нет

Ни одного чтения — значит и тонкостей переноса Code-2 (адаптивная комиссия, переход
через неинициализированные корзины) здесь нет: они целиком внутри той ошибки, которую
мерит замер. Сеть не трогалась, симуляция не запускалась, чужие файлы не правились.

## Встроено Code-1 (01.10, утренний пакет, п.1) -- что именно стоит в полосе

Тень включается флагом и по умолчанию ВЫКЛЮЧЕНА: `BLOOM_DLMM_BEZ_CHTENIY=1`
(и/или `BLOOM_DLMM_BEZ_CHTENIY_GROUPS=<группы>` -- список групп сильнее общего
флага). Группа сигнала протянута в `массивы_dlmm_сейчас` именно для этого.

Обёртка -- `bloom_own_send.тень_нуля_чтений`, вызов -- рядом с тенью одного
чтения, доступ из сборки -- `тень_dlmm_нуль`. Модуль решений не принимает и
`min_out` для отправки не отдаёт: **min_out тени считает обёртка**, ТОЙ ЖЕ
формулой, что денежный путь (`int(ожидаем * (1 - проскальзывание))`), и только
чтобы положить рядом с боевым.

Семь полей в запись позиции и в выгрузку Code-2:

| поле | что в нём |
|---|---|
| `lane_dlmm_nol_godilos` | True/False/None -- посчиталось И НЕ завышено |
| `lane_dlmm_nol_why_not` | причина словами, когда не True |
| `lane_dlmm_nol_cena_polosy` | `expected_out` боевой точной котировки |
| `lane_dlmm_nol_cena_teni` | `expected_out` нуля чтений |
| `lane_dlmm_nol_min_out_polosy` | min_out ИЗ ОТВЕТА котировки (тот, что уходит в tx) |
| `lane_dlmm_nol_min_out_teni` | min_out, который дала бы цена тени |
| `lane_dlmm_nol_otklonenie_pct` | (тень − полоса) / полоса, в процентах |

Боевой минимум берётся ИЗ ОТВЕТА котировки, а не пересчитывается: пересчёт мог
бы разойтись с числом, которое реально ушло в транзакцию. Это отдельная
самопроверка (`min_out` в ответе ставится числом, которое из цены не выводится).

Расхождение больше порога -- ОТДЕЛЬНОЙ строкой в TG, один раз на сделку, после
строки BUY: `c2_doklad_format.строка_тени_нуля`, порог
`BLOOM_DLMM_NOL_POROG_PCT` (по умолчанию 1.0 %). На совпадениях строки нет
нарочно: числа и так лежат в записи и в выгрузке.

Знак отклонения -- смысловой: ПЛЮС значит, что нуль чтений обещает больше, чем
пул отдаёт, то есть его min_out был бы завышен и сделка откатилась бы; МИНУС --
отправка прошла бы с запасом. Так и написано в строке словами.

Самопроверки: `bloom_own_send` 547/547, `c2_doklad_format` 93/93,
`bloom_detector` 580/580. Числа в проверках строки -- из живого замера Code-3
(`data/stroiteli/dlmm_bez_chteniy_chislo.json`): худшая строка 6.638 %
(предсказ 292 784 022 при факте 274 558 885), p90 0.9615 % и точное совпадение
53 954 962 = 53 954 962; синтетических процентов в них нет.

## Дополнение 03.10 (вечер): ПРИ БОЛЬШОМ СКАЧКЕ — ОТКАЗ, и оба предела замерены

**Слово владельца:** «минимум выхода из цены источника с запасом 5 % / 10 %,
счета из его транзакции; при большом скачке — отказ».

Запас 5 % / 10 % был и раньше (он приходит снаружи, параметром
`проскальзывание`). Чего не было — отказа на скачке: модуль считал цену всегда и
лишь **помечал** `корзин_доказано=False`. Теперь это два отказа по имени, и у
обоих есть число.

### Два предела

| предел | значение по умолчанию | флаг | почему именно так |
|---|---|---|---|
| корзин у свопа источника | **10** | `BLOOM_DLMM_NOL_PREDEL_KORZIN` | мы берём его **среднюю** цену, а свой своп начинаем с его **последней** корзины, то есть завышаем примерно на половину его скачка. Шаг корзины у живых пулов замерен по цепи (`data/dlmm_shag_korziny.json`): 100 bps у 8 пулов из 11, 200 у двух, 125 и 20 по одному. При шаге 100 bps десять корзин — это 1.01¹⁰ = +10.5 % цены, половина +5.1 %, то есть ровно запас 5 % |
| доля размера (наш вход / его вход) | **1.0** | `BLOOM_DLMM_NOL_PREDEL_DOLI` | если наш вход больше его, число корзин **не доказано**: за его последней корзиной ликвидность может быть любой, вплоть до нуля |

Оба предела снимаются нулём (`предел_корзин=0`, `предел_доли=0`) — замер обязан
уметь мерить и без них, иначе он подтверждал бы сам себя.

Скачок — причина **откатная**: путь двух чтений считает по состоянию, и скачок
источника ему не мешает.

### Замер: сколько прошло бы и сколько отказало при каждом запасе

`python3 analysis/c2_dlmm_bez_chteniy.py --zamer data/dlmm_bez_chteniy_zapas.json`

Проверка без сети: берём своп A и своп B **одного пула в одну сторону**,
предсказываем выход B по цене A на РАЗМЕРЕ B и сравниваем с тем, что B получил
на самом деле. В репозитории таких пар **21**, и зазор между ними — от 38 до
1 245 304 слотов. Горячий путь отстаёт от источника на **1–3 слота**, поэтому
числа идут по полосам зазора, а не одной кучей: пара с зазором в сто тысяч слотов
мерит дрейф цены за сутки, а не этот путь.

**Зазор ≤ 100 слотов — 5 пар (только они говорят о горячем пути):**

| | посчитано | отказов | завысили >1 % | прошло при 5 % | прошло при 10 % |
|---|---|---|---|---|---|
| **с пределами** (как в модуле) | 3 | **2** (оба — скачок) | **0** | **3 из 3** | **3 из 3** |
| без пределов | 5 | 0 | 2 | 3 из 5 | 5 из 5 |

Отклонения трёх посчитанных: **−7.62 %, −5.76 %, −1.28 %** — ни одного завышения.
Две отказанные строки — это ровно те, что завышали: **+10.41 %** при доле 1.67 и
**+9.33 %** при доле 1.00.

**Вся выборка (21 пара, зазоры до 1 245 304 слотов):** с пределами посчитано 10,
отказано 11, медиана +7.02 %, максимум +107 %, прошло при 5 % и при 10 % — 5 из
10. Без пределов: 21 посчитано, 11 завышений, максимум +149 %, прошло 10 из 21
при 5 % и 12 из 21 при 10 %. **Это не вердикт пути**, а цена вопроса «насколько
устарела цена»: на таких зазорах ошибка — чужие сделки между A и B, а не
арифметика.

### Что из этого следует для решения штаба

* **Запас 5 % достаточен** на горячем расстоянии, **если пределы скачка стоят**:
  3 из 3, ни одного завышения.
* **Цена пределов** — отказ на 2 сигналах из 5 (40 %). Отказ не потеря: полоса
  уходит прежним путём в два чтения, то есть платит то же, что платит сейчас
  (замер на хосте 30.09, `data/dlmm_dva_puti.json`: два чтения 39.8 мс p50,
  одно -- 20.4 мс; замер один).
  То есть пределы превращают «иногда дешевле, иногда мимо цены» в «дешевле там,
  где это безопасно».
* **Запас 10 % без пределов** закрывает все пять — но отдаётся с КАЖДОЙ покупки,
  и это решение владельца, а не строителя.
* **Выборки мало.** Пять пар — это пять пар. Главное число по-прежнему сбор
  Code-2 (46 свопов подряд: посчитать можно 31, отказ 15 — обратная сторона; при
  5 % прошло 30 из 31, при 10 % — 31 из 31, максимум +6.64 %), и оно согласуется
  с этим: тот сбор брал свопы ПОДРЯД, то есть зазор ещё меньше.
