Правило задано заранее: на семи сутках подбора источники ранжируются по итогу забора
S+0 (вход в блок источника, цена конца его слота), верхние K торгуют следующие сутки.
Подбор — **02–09.10** (последние сутки, прочитанные целиком; 10.10 в кэше 15 часов из
24, поэтому в подбор не идёт). Удержание H108 слотов, билет — предельный по глубине
(2 % резерва, не больше 3 SOL), поправка круга k 0.989.

**Это кандидат на проверку, а не вывод.** На 40 полных сутках забор набором по честной
цене (S0_дно, доля попадания 0.209) не проходит стандарт: 0 сочетаний из 324, лучший
p 2.59·10⁻⁴ против порога 1.54·10⁻⁴. И состав неустойчив: при другом случайном розыгрыше
попадания верхние 5 совпадают на 0–1 кошелька из 5.

## Чем сверять первые 100 сделок

Ожидание на сделку и на первые сто сделок по тому же правилу и тем же сутках проверки
(H108, k 0.989). Две цены: **S0_дно** — честная, конец слота источника (замер живьём:
доля наплыва слота q при лаге 0 — медиана 0.99); **S0_сер** — середина наплыва слота,
то есть если бы мы садились вдвое раньше.

Читать так: **при билете 0.01 ожидание отрицательное при любой цене** — на таком билете
видны только издержки (медиана круга 0.002 SOL), а не стратегия; суток в плюсе 0 из 16.
Гипотезы различает билет **0.1**: честная цена даёт около нуля с минусовой медианой
(−0.004 на сделку, то есть больше половины сделок в минусе), середина слота — +0.0104 на
сделку и 14–15 суток из 16 в плюсе. Если живьём на ста сделках при 0.1 выйдет −0.2…+0.25
с минусовой медианой — это честная цена; если +0.4 и выше с плюсовой медианой — мы
садимся раньше, чем показывает замер q.

Сверка живых сделок считается командой
`python3 analysis/podbivka_cena_v_slote.py --vhod <выгрузка> --sravnit
data/podbivka/cena_v_slote_4vw.json` — она даст q по каждому источнику отдельно (q при
лаге 0, доля сделок с лагом 0, транзакций между источником и нами).
