# DLMM без чтений: котировка по событию предыдущего свопа (46 свопов сверки v6)

Модель строителя без getMultipleAccounts: корзина -- end_bin_id предыдущего успешного свопа пула, ставка -- его fee_bps, bin_step из кэша, налог Token-2022 на входе -- по минту; содержимого корзин нет, весь вход -- по цене одной корзины. Факт -- amount_out события сделки. Пол min_out = модель × (1 − запас): факт ≥ пола -- «в пол» (сделка прошла бы), меньше -- «отказ». Для сравнения -- котировка по прочитанному состоянию (сверка v6, data/podbivka/dlmm_proverka_mnogo4.json). Скрипт: analysis/podbivka_dlmm_bez_chteniy.py.

**Оговорки.** (1) Столбец «с чтением» -- как в сверке v6: вход подавался до налога Token-2022, поэтому 6 из его 7 ошибок
> 1 % -- налог 1 % / 3 % (ошибка сверки, не модуля; см. docs/podbivka_dlmm_proverka.md), седьмая -- необъяснённый своп
`2x46Pfzr` (−2.74 %). Модель без чтений берёт вход после налога. (2) Предыдущий своп пула -- почти всегда соседняя
транзакция пула (транзакций между: 0 у 40 из 46), поэтому корзина из события совпадает с корзиной в момент сделки; в торговом
пути это событие своп источника, и между ним и нашей покупкой могут встать чужие свопы -- этого здесь нет. (3) Ошибки без
чтений > 1 %: `23dda97h` (12 корзин, +5.66 %), `5jZfyqfu` (3 корзины, +1.10 %), `FLJn5Qga` (−1.38 %, налог 3 % на входе);
модель одной корзины завышает выход, когда своп проходит несколько корзин. Отказ при запасе 5 % -- `23dda97h`.
