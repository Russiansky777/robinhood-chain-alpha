`whirLbMiicVdio4qvUfM5KAg6Ct8VwpYzGff3uctyCc` из github.com/orca-so/whirlpools (коммит f4b99e79, 29.09.2026):

`manager/fee_rate_manager.rs` + `state/oracle.rs` (адаптивная комиссия), `util/sparse_swap.rs` (последовательность массивов),

## Шаги в торговом пути

1. **Пул** -- счёт `whirlpool` инструкции swap (счёт 2) / swap_v2 (счёт 4) в транзакции источника (или событие Traded).
2. **Чтение 1:** `getAccountInfo(пул)` → `pool = разобрать_пул(...)` (tick_spacing, fee_rate, protocol_fee_rate, liquidity,
   sqrt_price, tick_current_index, минты и хранилища).
3. **Какие массивы:** покупка токена за SOL -- `a_to_b = (pool["token_mint_a"] == WSOL)`;
   `старты = старты_последовательности(pool, a_to_b)` (3 старта), адреса -- `адрес_массива(пул, старт)`; oracle -- `адрес_оракула(пул)`.
4. **Чтение 2 -- одним запросом:** `getMultipleAccounts([пул, oracle] + 3 адреса массивов)`. Итого 5 счетов.
   Несозданный массив (null) -- передать в котировку как отсутствующий (будет пустым), в инструкцию -- его адресом.
   Oracle null -- у пула нет адаптивной комиссии (`разобрать_оракул(None)` → None).
5. **Котировка:** `q = котировка_точный_вход(pool, {старт: разобрать_массив(...)}, разобрать_оракул(oracle), вход, a_to_b, unix_время)`.
   `q["amount_out"]` -- что отдаст хранилище (сырые единицы); `unix_время` -- ожидаемое время сделки (адаптивная комиссия,
   открытие торговли `trade_enable_timestamp`). Своп длиннее трёх массивов программа не проведёт -- модуль даст ошибку.
6. **Инструкция swap_v2:** tick_array_0..2 = три адреса из шага 3 (порядок не важен), oracle = PDA (всегда, по живым сделкам --
   во всех 286 из 286). Налог Token-2022: программа считает на `amount − transfer_fee` входа; выход уменьшается налогом минта выхода.
7. **min_out** = `q["amount_out"] × (1 − проскальзывание)` (за вычетом налога выхода, если есть).

## Что не входит

- exact_out; two_hop_swap; transfer hook; сделки между чтением и нашей покупкой.
