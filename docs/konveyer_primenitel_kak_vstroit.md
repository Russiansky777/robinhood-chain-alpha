# Применитель конвейера (Правило 18): как врезать, что проверено и чего нет

Модуль: `analysis/c3_konveyer_primenitel.py` (самопроверка **55/55**,
`python3 analysis/c3_konveyer_primenitel.py`). Файл групп он **не пишет вовсе** —
выдаёт правку, которую прогоняет Code-1 существующим применителем групп
`deploy/checks/pravka_grupp.py` (у него самопроверка денежного пути).
База — голова `claude/nifty-sagan-r0polg`, слита в `claude/stroiteli` (правило 8).

## 1. Что делает и чего не делает

| | |
|---|---|
| **вход** | `data/konveyer/<дата>.json` Code-2 (разбор источников по цепи) + живой файл групп |
| **выход** | `data/konveyer/pravka_<дата>.json` — план для `pravka_grupp.py --plan`; `data/konveyer/primenitel_<дата>.json` — отчёт со всеми отказами; `data/konveyer/primenitel_zhurnal.json` — что уже выдано, по датам |
| **делает** | добавление адреса в группу `konveyer`, не больше **5 в сутки**, только из раздела `добавить` |
| **не делает** | не снимает, не переводит из группы в группу, не правит поля, не создаёт групп, не пишет файл групп, не трогает сеть и не торгует |

Отказов в отчёте обычно больше, чем добавлений, и **каждый назван словами** — по
ним видно, чем конвейер заткнуло, и чинится причина, а не предел.

## 2. Порядок прогона

```bash
# 1. Code-3 (или кто угодно: сети и ключей не нужно) -- посмотреть решение
python3 analysis/c3_konveyer_primenitel.py --vhod data/konveyer/2026-10-04.json \
        --gruppy data/sources_live.json --pokazat

# 2. записать правку, отчёт и журнал
python3 analysis/c3_konveyer_primenitel.py --vhod data/konveyer/2026-10-04.json \
        --gruppy data/sources_live.json

# 3. СВЕРИТЬ правку прямо перед применением: годна ли она СЕЙЧАС
python3 analysis/c3_konveyer_primenitel.py --sverit data/konveyer/pravka_2026-10-04.json \
        --gruppy <живой файл групп>

# 4. Code-1 -- применить правку ЕГО применителем, с самопроверкой денежного пути
python3 deploy/checks/pravka_grupp.py --file <живой файл групп> \
        --plan data/konveyer/pravka_2026-10-04.json
```

**Шаг 3 не для порядка, а на деньгах.** Вся безопасность правки держится на одном:
каждый её адрес лежит в файле групп **нигде**, и тогда `perenesti` — чистое
добавление. Но файл живой: между записью правки и её применением адрес мог
попасть в группу (своим прогоном, правкой владельца, чем угодно) — и та же
операция `perenesti` **сняла бы его оттуда**. Сверка перечитывает файл групп и
отвечает, годна ли правка СЕЙЧАС; не годна — код выхода 3, применять нельзя,
надо прогнать применитель заново. Она же проверяет вид правки: ни одной операции,
кроме добавления в `konveyer` (даже если её подложили руками).

`--gruppy` не задан — читается тот файл, который читает служба
(`BLOOM_SOURCE_GROUPS`, по умолчанию `data/sources_live.json` — 03.10 Code-1
переименовал прежний `sources_2026-09-25.json` в `..._USTAREL_2809.json` и положил
рядом выгрузку с хоста).

**Ключи, у которых есть денежная сторона** (все три — после встречного разбора,
раздел 9):

* `--kat` переносит правку и отчёт в другой каталог, **а журнал — нет**. Журнал
  всегда `data/konveyer/primenitel_zhurnal.json`, если не задан `--zhurnal`:
  иначе один прогон с чужим `--kat` выдал бы ещё пятёрку сверх пятёрки, ничего
  формально не нарушив.
* `--predel` пятёрку **только понижает**. `--predel 50` — отказ целиком
  («предел больше 5 не берётся»): пятёрка — слово владельца, а не значение по
  умолчанию, и обходить его ключом командной строки нельзя.
* `--pokazat` **ничего не записывает и говорит об этом словами** в stderr:
  «НЕ ДЛЯ ПРИМЕНЕНИЯ… журнал НЕ записан, суточный предел этими адресами НЕ
  занят». Напечатанное можно перенаправить в файл и применить — и тогда журнал
  этой пятёрки не увидит, а следующий прогон выдаст её снова.

## 3. Что должно быть СДЕЛАНО ДО первого прогона

**Группа `konveyer` в файле УЖЕ ЕСТЬ** (создана Code-1 03.10; в `data/sources_live.json`
у неё `lane_size` = `lane_sol` = 0.1, `lane_trades` 1, `bloom_trades` 0 и **два
адреса** — первый по слову владельца, второй выдан этим применителем). Этот
абзац остаётся, потому что проверка осталась: применитель группу **не создаёт**
и отказывает по имени, если её нет («в файле групп нет группы konveyer —
добавлять некуда»); создаёт её Code-1 тем же
`pravka_grupp.py --sozdat konveyer --politika '{...}'`, а числа политики —
решение владельца.

**Проверено на живом файле:** на том же файле Code-2 за 03.10 применитель теперь
**отказывает** — «адрес уже в группе konveyer», добавлено ноль, и так даже с
пустым журналом. То есть повторная выдача уже применённого адреса невозможна
двумя путями независимо. Что из политики **читает денежный путь** (проверено по коду,
не по памяти):

| поле | кто читает | если не задать |
|---|---|---|
| `lane_size` | `bloom_source_groups` (кладёт его же в `lane_sol`) | размер из окружения `BLOOM_OWN_SEND_SOL` (0.01) |
| `lane_sol` | — | **не задавать вместе с `lane_size`**: если числа разные, загрузчик ставит группе `lane_trades=false` и она не торгует вовсе |
| `lane_trades` | `bloom_own_send.полоса_торгует` | торгует (отсутствие = «да») |
| `bloom_trades` | детектор | не торгует площадкой |
| `lane_pools` | `bloom_own_send._типы_из_файла` | типы из флагов окружения. **Только списком**: строку читатель молча отбрасывает (у `pravka_grupp` на это есть гейт при создании группы) |
| `lane_open_max`, `hold_slots`, `min_target_sol`, `slippage`, `fanout`, `subscribe` | полоса и детектор | свои умолчания |

## 3б. Вид входа — что именно я читаю у Code-2 (форма, не данные)

Имя файла — **`<дата>.json`** (`2026-10-04.json`): дата берётся из имени и
обязана совпасть с полем `дата` каждого ряда. Ряды — список словарей; ключ
списка может быть `ряды`, `адреса`, `источники`, `rows` или `строки` (берётся
первый найденный, и какой взят — пишется в отчёт полем `klyuch`). Либо файл сам
список.

```json
{
  "дата": "2026-10-04",
  "кусты": {"<имя куста>": ["<адрес>", "<адрес>"]},
  "ряды": [
    {"адрес": "<base58>", "дата": "2026-10-04", "раздел": "добавить",
     "n": 23, "среднее": 0.11, "медиана": 0.08, "в_плюсе": 0.61,
     "толпа": 3, "медиана_1": 0.07, "медиана_2": 0.09,
     "суток_в_плюсе": 3, "последние_сутки": 0.05,
     "типы_пулов": ["pump_amm", "cpmm"], "доля_usdc": 0.2, "куст": "k12"}
  ]
}
```

Это **форма, а не данные**: ни одного настоящего адреса здесь нет, числа
условные. Все 15 полей ряда обязательны — нет любого, и ряд получает отказ с
именем поля (значения не перепроверяются: считает Code-2).

**Поле `кусты` необязательное, но просьба его присылать.** Без него «куст с
действующим источником» ловится только по адресам, которые есть в самом файле;
с ним — по всему кусту (см. раздел 7). Это одна строка на его стороне и
закрытое слепое пятно на моей.

| `раздел не «добавить»` | ряд из другого раздела |

| `адрес в log_only — его уже слушают, перевод не наше дело` | |
| `адрес в off — выключен прямым словом, конвейер его не включает` | |
| `адрес уже в группе konveyer` | правку этого адреса уже применили |
| `адрес лежит в контейнере группы <имя>.<контейнер>` | см. раздел 6 — ловушка `dropped_by_credits` |
| `куст уже действует: его источник в торгующей группе` | у куста уже есть действующий источник |
| `куст уже взят в этой же партии` | из одного куста берётся ровно один адрес |
| `уже выдан в правку этим применителем: <дата>` | повтор того же файла |
| `суточный предел 5 исчерпан` | шестой и далее |

| `адрес уже взят в этой же партии (дубль в файле Code-2)` | один адрес дважды в рядах-списком |

| `у группы konveyer поле addresses — СПИСОК…` | **отказ целиком**, см. раздел 9: применитель групп сотрёт всё, что в группе лежит |
| `группа konveyer не торгует (сняты оба признака)` | **отказ целиком**: добавление ушло бы в мёртвую группу |
| `у группы konveyer lane_size и lane_sol РАЗНЫЕ…` | **отказ целиком**: загрузчик служб сам снимает ей `lane_trades` |
| `предел больше 5 не берётся` | `--predel` выше пятёрки |
| `правка за эту дату уже записана и не пустая…` | повторный прогон не затирает непустую правку пустой (код выхода **4**) |
| `в правке больше добавлений, чем осталось по журналу` | только в `--sverit`: правка, дописанная руками сверх суточного остатка |
| `у правки нет даты…` | только в `--sverit`: ни поля `дата`, ни даты в имени файла — остаток предела не посчитать |

## 5. Что проверено числами (самопроверка 89/89)

* **предел 5**: шесть годных рядов → добавлено ровно пять, шестому отказ по
  имени предела; порядок — файла Code-2 (взяты места 1…5);
* **правка — только добавление**: пять операций, у каждой ровно три ключа
  (`perenesti`, `v`, `pometka`), `v` = `konveyer`; ни одной операции `otklyuchit`,
  `pole`, `znachenie`, `sozdat`, `udalit_pole` — для них в модуле нет кода;
* **повтор того же файла**: добавлено ноль, у каждого причина «уже выдан», а не
  «предел». Отдельно проверено, что **журнал и файл групп нужны оба**: с
  применённой правкой пять адресов получают «уже в konveyer», но шестой (которого
  в группе нет) стал бы годным — его держит только журнал;
* **битый вход** (не JSON, пустые ряды, ряд не словарь, файла нет, имя не того
  вида): отказ словами, применитель не «ок», код выхода не ноль;
* **чужая дата**: отказ целиком;
* **отказы по состоянию адреса**: торгующая группа, `log_only`, `off`,
  `konveyer`, контейнер `dropped_by_credits` — каждый своим именем;
* **без любого из 15 обязательных полей** — отказ с именем поля (проверено по
  каждому полю отдельно, 15 из 15);
* **кусты**: действующий источник куста (и по рядам файла, и по карте `кусты`,
  если Code-2 её прислал) — отказ; из куста в партии берётся ровно один;
* **сверка перед применением**: на чистом файле правка годна целиком; на файле,
  куда её уже применили, — отказ «правка устарела» по всем пяти адресам (иначе
  `perenesti` снял бы их); операция не-добавление и пустой список `pravki` —
  отказ по имени;
* **вид адреса**: ключ Solana узнаётся, `"None"`, `" x "`, `None` и 44 нуля —
  нет; ряд с таким «адресом» получает отказ по имени, а не уходит ключом в живой
  файл групп;
* **дубль в одном файле**: один адрес дважды → взят один, второму отказ по
  имени (ряды-списком повтора не запрещают);
* **окно даты**: файл за прошлый месяц — отказ целиком; ровно на краю окна
  (±2 суток) ещё годен; сутки между датами считаются числом (1, 32, `None` на
  неразобранной дате). Проверки «сегодня» подставляют дату сами — самопроверка
  не смотрит на календарь и не покраснеет через трое суток сама по себе;
* **`addresses` списком у `konveyer`**: вид поля назван («список», в нём 2
  адреса), применитель отказывает целиком, **и сверка перед применением тоже** —
  вид поля мог стать списком уже после записи правки. Пустой список — не отказ:
  сотрётся ничто;
* **целевая группа обязана торговать**: оба признака сняты — отказ по имени;
  разные `lane_size` и `lane_sol` — отказ **именем спора размера** (чинится он
  иначе: одним полем правды в файле групп);
* **предел**: `--predel 50` — отказ целиком, `--predel 2` — ровно два; в сводке
  остаток **после** партии (0) и отдельно до неё (5);
* **пустая правка не затирает непустую**: отказ словами, байты файла правки
  не изменились (сверено `read_bytes()` до и после);
* **журнал не едет за `--kat`**: лёг в каталог по умолчанию, в каталоге из
  `--kat` его нет;
* **`--pokazat`**: код 0, в stderr «НЕ ДЛЯ ПРИМЕНЕНИЯ», на диске ни правки, ни
  журнала (прогнан `main()` целиком, с перехватом вывода);
* **сверка считает остаток предела по журналу**: правка, дописанная руками
  сверх остатка, — отказ по имени предела; правка этого применителя остаток не
  превышает (её адреса уже в журнале, дважды они не считаются); правка без даты
  — отказ;
* **кусты на живом файле НЕ названы**: `куст: null` у всех 48 рядов
  (`кустов_убрано: 0` у Code-2) → в сводке `кустов_не_названо: 1`, а не
  молчание. Это замер, а не догадка: по этому файлу мой разбор куста не делает
  **ничего**;
* **конец в конец**: правка прогнана `pravka_grupp.применить` на КОПИИ файла
  групп — каждая операция принята (код 0), он ждёт эти адреса именно в
  `konveyer`, правок полей и убранных полей не увидел; после записи
  `bloom_source_groups.группа()` отдаёт `konveyer` для добавленного, а чужие
  адреса остались в `batch5`, `log_only` и `off`.

## 6. Ловушка, из-за которой правка могла бы СНЯТЬ адрес

Это стоит отдельного раздела, потому что нашлось при разборе чужого кода, а не
было задумано.

Операция `perenesti` у `pravka_grupp.py` **снимает** адрес из всех контейнеров
`КОНТЕЙНЕРЫ = (addresses, by_signal, snipers, dropped_by_credits)` и кладёт в
целевую группу. А `bloom_source_groups.загрузить()` строит карту «адрес →
группа» только по **addresses, by_signal и snipers** — `dropped_by_credits` в
неё **не входит**.

Значит адрес, лежащий только в `dropped_by_credits` торгующей группы, модулю
службы виден как «нигде» (`группа()` отдаёт `off`), и правка «перенести в
konveyer» **тихо сняла бы его оттуда** — ровно то, что владелец запретил
(«ничего не снимает и не переводит»).

На живом файле 03.10 таких адресов **ноль** (у всех пяти групп заполнен только
`addresses`: 1 + 12 + 10 + 9 + 591 = 623, и карта службы совпадает с сырым файлом
адрес в адрес) — то есть ловушка сейчас не сработала бы. Но контейнер в формате
есть, применитель групп его чистит, и ждать, пока в нём что-то появится, незачем.

Поэтому состояние адреса здесь проверяется **по сырому файлу и по всем четырём
контейнерам**, а карта модуля службы берётся отдельно и только как второе мнение;
где они расходятся, верх берёт сырой файл. В самопроверке это закрыто тремя
проверками: модуль службы такой адрес не видит (отдаёт `off`), применитель
конвейера видит его в сыром файле, и ряд получает отказ с именем контейнера.

## 7. Чего применитель НЕ знает

* **куст адреса, которого нет в файле Code-2.** Кусты считает он; по чужим
  адресам карты у меня нет. Поэтому «куст действует» ловится только по тем
  адресам файла, что уже лежат в торгующих группах, **плюс** по карте `кусты`,
  если Code-2 её прислал (необязательное поле верхнего уровня
  `{"кусты": {"<имя куста>": ["<адрес>", ...]}}`). Если Code-2 будет присылать
  эту карту всегда — слепое пятно закрывается целиком, и это одна строка на его
  стороне;
* **два разных файла на одну дату.** Предел считается по журналу, то есть по
  сумме выданного за дату: второй файл того же дня добавит только остаток до
  пяти. Журнал за `--kat` больше **не едет** (см. раздел 9.6), так что обойти
  счёт чужим каталогом уже нельзя; задать другой журнал можно только прямо —
  `--zhurnal`, и это видно в командной строке;
* **одновременные прогоны.** Замка нет: два процесса с одним журналом могут
  выдать больше пяти. Прогон ручной и один, но если он станет автоматическим,
  замок нужен;
* **свежесть цифр Code-2.** Применитель не перепроверяет ни медиану, ни
  «суток_в_плюсе» — он проверяет, что поля ЕСТЬ, и переносит их в пометку
  адреса. Считает Code-2, и спорить с его разбором, не видя данных, нечем.

## 8. Чего в модуле нет

Ни одной сделки, ни одного чтения сети, ни одной правки файла групп, ни одного
снятия и перевода. Группу создаёт и правку применяет Code-1; числа политики —
слово владельца.

## 9. Встречный разбор (пять сторон): что нашлось и что из этого — диф для Code-1

Разбор был заказан против себя: пять сторон — деньги, повтор, вид входа, чужой
применитель, командная строка. Ниже — только то, что подтвердилось **прогоном**,
а не рассуждением. Всё, кроме 9.1, уже исправлено в модуле и закрыто
самопроверкой (86/86).

### 9.1. ДИФ №6 ДЛЯ CODE-1 (общий код, сам не правлю): `perenesti` СТИРАЕТ группу, у которой `addresses` — список

**Это самое дорогое из найденного, и оно в общем коде.**
`deploy/checks/pravka_grupp.py:225`:

```python
        if not isinstance(цель.get("addresses"), dict):
            цель["addresses"] = {}
```

Файл групп держит адреса **двумя видами** — словарём `{адрес: партия}` и списком
объектов с полем `address` (это читает и `bloom_source_groups.загрузить()`, см.
его же комментарий «оба читаем, третий вид не изобретаем»). Если у целевой группы
`addresses` оказался **списком**, строка выше заменяет его пустым словарём — и
**все адреса, которые в группе уже лежали, исчезают**.

Проверено своим прогоном на копии: было
`addresses: [{"address": "AAA1"...}, {"address": "BBB2"...}]` → стало
`{"NEW3": "конвейер"}`, **код выхода 0**, самопроверка денежного пути прошла
зелёной (она смотрит только на затронутый адрес и спрашивает его группу — а он на
месте). То же место второй раз — `pravka_grupp.py:251` в `otklyuchit`.

Нужная правка — пять строк, обе точки одинаково:

```python
        было_адресов = цель.get("addresses")
        if isinstance(было_адресов, list):   # СПИСОК НЕ ТЕРЯТЬ, А ПЕРЕВЕСТИ
            цель["addresses"] = {str(о.get("address") if isinstance(о, dict) else о):
                                 (о.get("почему") if isinstance(о, dict) else None) or "было списком"
                                 for о in было_адресов if (о.get("address") if isinstance(о, dict) else о)}
        elif not isinstance(было_адресов, dict):
            цель["addresses"] = {}
```

**Диф проверен прогоном, а не глазами.** Две копии `pravka_grupp.py` (своя и с
этими пятью строками), один и тот же файл групп, один и тот же план
(`perenesti ALL1V7x5… -> konveyer`), у группы `konveyer` в `addresses` список из
двух адресов:

| копия | что стало с `konveyer.addresses` | код | его самопроверка |
|---|---|---|---|
| как есть | `{"ALL1V7x5…": "конвейер проба"}` — **AAA1 и BBB2 потеряны** | 0 | пройдена |
| с пятью строками | `{"AAA1pV7x5…": "ранний", "BBB2pV7x5…": "ранний", "ALL1V7x5…": "конвейер проба"}` | 0 | пройдена |

Обрати внимание на второй столбец «код» и третий: **в обоих случаях ноль и
«самопроверка денежного пути пройдена»** — то есть потерю не видно ни по коду
выхода, ни по его проверке.

Сильнее было бы добавить в его самопроверку денежного пути одно число: **сколько
адресов было в затронутых группах до правки и сколько стало** — расхождение не в
пользу роста означает потерю. Это его файл и его самопроверка; делать не берусь.

**Пока диф не взят**, мой применитель **отказывает целиком**, если у `konveyer`
`addresses` — непустой список: и в самом прогоне, и в `--sverit` перед
применением (вид поля мог стать списком уже после записи правки). Пустой список
пропускается: сотрётся ничто.

### 9.2. Мусор вместо адреса уходил в живой файл групп

В правку шла строка из поля `адрес` **без проверки вида**. Применитель групп
положит её ключом так же охотно, его самопроверка денежного пути её пропустит
(она сверяет группу по тому же ключу), а служба отнесёт такой ключ к **группе по
умолчанию**. Теперь адрес проверяется как ключ Solana (32 байта base58, через
`solders`), иначе — отказ по имени.

### 9.3. Один адрес дважды в одном файле съедал две единицы предела

Ряды приходят и словарём (ключи сами не повторятся), и **списком** — список
повтора не запрещает. Было бы: две операции в правке и минус две единицы
пятёрки за один источник. Теперь второму — отказ по имени.

### 9.4. Файл за прошлый месяц проходил как свежий

Дата сверялась с **именем файла и рядами**, то есть сама с собой. Файл
`2026-08-20.json` сверится сам с собой, журнал за ту дату пуст — и выдалась бы
пятёрка «свежих» адресов, посчитанных по мёртвому окну. Теперь дата обязана
лежать в окне **±2 суток** от сегодняшней (`OKNO_DATY_SUTOK`), иначе отказ
целиком. Умышленного обхода нет **нарочно**: нужен файл за другой день — его
присылает Code-2 заново.

### 9.5. Добавление в мёртвую группу выглядело как работа

Проверялось «группа `konveyer` в файле **есть**». Но у группы могли быть сняты
оба признака торговли, или — тише — у неё могли разойтись `lane_size` и
`lane_sol`: тогда загрузчик служб **сам** снимает ей `lane_trades`
(`bloom_source_groups`: «два разных числа — группа не торгует»). В обоих случаях
отчёт зелёный, адресов прибыло, денег нет. Теперь это два отдельных отказа — и
спор размера назван своим именем, потому что чинится он иначе: одним полем
правды в файле групп.

### 9.6. Суточный предел обходился ключом командной строки

Три дыры, все закрыты:

* `--predel 50` — брался молча. Теперь пятёрку можно только **понижать**.
* журнал лежал в каталоге из `--kat` — то есть один прогон с чужим каталогом
  начинал счёт с нуля. Теперь журнал всегда `data/konveyer/primenitel_zhurnal.json`,
  если не задан `--zhurnal`.
* `--pokazat` печатал правку и **молчал** о том, что журнал не записан.
  Напечатанное перенаправляется в файл одной командой. Теперь говорит словами.

### 9.7. Пустая правка затирала непустую

Второй прогон того же файла даёт **ноль** добавлений — и это правильно (журнал
помнит). Но запись такой правки поверх прежней стирала ровно тот файл, который
Code-1 ещё не применил или держит как запись о сделанном, **с нулевым кодом
выхода**. Теперь — отказ словами и код выхода 4; байты правки на месте
(проверено `read_bytes()` до и после).

### 9.8. Сверка не считала остаток предела

`--sverit` проверял вид операций и состояние адресов, но не **число**. Правку
можно дописать руками: «только добавление в `konveyer`» соблюдено, пятёрка — нет.
Теперь сверка читает журнал по дате правки (дата лежит и полем `дата` в самой
правке) и отказывает, если добавлений больше остатка; адреса, которые этот
применитель уже выдал за эти сутки, дважды не считаются.

* **`куст: null` у всех рядов живого файла.** Разбор куста есть, но по этому
  файлу он не делает ничего. Отказом это не сделано: так я отверг бы
